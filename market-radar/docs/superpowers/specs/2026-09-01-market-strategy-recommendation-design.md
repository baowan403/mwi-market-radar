# MWI Market Radar：市場策略推薦設計

日期：2026-09-01（Asia/Taipei）

狀態：Owner 已確認產品方向，待書面規格審閱

範圍：設計與規劃，不代表功能已完成或已部署

## 1. 產品目標

MWI Market Radar 不再以「另一個行情網站」為目標。公開行情只負責提供可信的市場背景；核心價值是把角色快照、遊戲配方、最新市場與歷史量價資料合併，產生玩家能執行的獲利策略。

產品必須回答四個問題：

1. 以這名玩家目前的技能、裝備、茶、房屋與增益，現在走哪條完整路徑的理論收益最高？
2. 扣除 5% 稅、原料採購、耗材、成功率與多步工時後，這條路徑的真實成本與收益是多少？
3. 市場是否足以承接玩家不間斷生產；若不足，安全批量、可製作時數及售完天數是多少？
4. 這條策略的利潤與成交量在 1D／3D／7D 內是擴張、持平或壓縮；玩家應立即執行、限量試單、提前備料、等待確認或停止？

以下五項是正式策略排行榜的硬門檻，缺一不可：

- 理論日利。
- 流動性調整後的可實現日利。
- 安全批量或可長掛時數。
- 3D／7D 策略利潤趨勢。
- 建議成立原因與失效條件。

如果功能只能顯示物品漲跌或重算 Milkonomy 的當下日利，即不具備足夠差異化，不應作為完成品發布。

## 2. 參考研究與重用邊界

### 2.1 Milkonomy

研究基準：`Polokikiki/Milkonomy`，檢查提交 `febe90f14f7ea1e51937cc888f6f6e1907c58fff`，MIT License。

可有效重用的既有方法：

- 正式市場資料直接讀取 MWI `game_data/marketplace.json`。
- 原料預設以賣一價購入，成品預設以買一價出售。
- 市場出售使用 `SELL_TAX_FACTOR = 0.95`；硬幣產物不重複課稅。
- 單步計算器已涵蓋採集、製造、分解、點金、轉化及強化等行為。
- `WorkflowCalculator` 會把多步中間品互相抵消，並依各步產能計算工時倍率。
- 利潤排行榜已能列舉單步與多步製造路徑。
- 現行匯入器可辨識：
  - Milkonomy Exporter `version: 1` 完整快照。
  - Milkonomy preset（`actionConfigMap`、`specialEquimentMap` 等）。
  - 部分戰鬥模擬器格式。
- 完整快照包括技能、裝備、房屋、社群增益、神龕、成就、茶與庫存等欄位。
- 繁體中文語系資料已存在，可作為 HRID 中文目錄產生來源之一。

採用方式：

- 不嵌入或依賴 Milkonomy 網站執行時狀態。
- 不直接搬入 Vue／Pinia UI 或整個應用程式。
- 將必要公式移植為無全域狀態的純 TypeScript domain modules。
- 保留 MIT attribution 與來源提交資訊。
- 以 Milkonomy 輸出建立 golden fixtures；相同角色、價格、路徑與假設下，基準理論收益應在明確容差內一致。
- Milkonomy 是公式一致性基準，不是我們的雲端後端，也不是策略趨勢資料來源。

### 2.2 牛牛股市

研究基準：`stockmarket.xin` 公開頁面與 GreasyFork userscript 1.0.4（MIT）。

已驗證的可借鑑做法：

- 雲端提供公開行情，不要求每位瀏覽者開著 MWI。
- 強化等級與精煉狀態是獨立市場標的。
- 可查看逐時賣一、買一、成交均價、成交量與成交價分布。
- 可把逐時資料彙整成長期日 K 與 OHLCV。
- 首頁顯示最新資料時間、物品數及資料狀態。

不採用的部分：

- 不依賴其未文件化、未承諾相容性的前後端 API。
- 不複製帳號、持倉、角色資產及密碼系統。
- 不攔截 React 內部物件或遊戲 WebSocket。
- 不讓缺價變成 0.00% 或把薄量巨幅波動當成正常機會。

## 3. 產品分層與資訊架構

### 3.1 第一層：公開市場看盤

任何人不導入角色也能使用：

- 繁體中文物品名稱、英文名稱與 HRID 搜尋。
- 自選物品、全市場及官方分類。
- 目前價、買一、賣一、價差、成交量。
- 1D／3D／7D 漲跌、波動與量能倍數。
- 逐時圖及長期日 K。
- 成交穩定、薄量、單邊、價差過大、量能放大、趨勢轉強／轉弱等客觀標籤。

物品行情列不得直接宣稱「可長掛」。可長掛是角色產能、完整策略與所有交易邊共同決定的結果，不是物品的固定屬性。

### 3.2 第二層：本機角色策略引擎

「策略推薦」頂層分頁始終可見。未導入快照時顯示用途、隱私說明與匯入入口，不顯示假設成玩家專屬的日利。

導入後解鎖：

- 立即可做：現在即可持續執行且通過流動性閘門。
- 限量套利：有正利潤，但只適合固定批量或短時間生產。
- 趨勢布局：目前未必第一名，但 3D／7D 利潤與需求正在改善。
- 自選策略：玩家釘選後持續監控整條路徑。

物品星號與策略星號分開保存：

- 物品自選監控單一市場標的。
- 策略自選監控完整輸入、輸出、利潤、容量與趨勢。
- 物品詳情可列出使用該物品的相關策略，但玩家不需先釘選物品才能被推薦策略。

## 4. 角色快照

### 4.1 第一版支援格式

優先支援兩種既有格式，不另創一套只能由本網站使用的新格式：

1. Milkonomy Exporter `version: 1` 完整快照。
2. Milkonomy preset 格式。

完整快照是推薦格式。Preset 若缺少神龕、成就、茶或房屋等欄位，仍可導入，但必須標記為「部分資料」，列出缺失欄位，相關策略不得顯示高信心。

第一個策略切片不要求直接讀取登入中的 MWI 頁面。待手動匯入與數值一致性驗證完成後，再評估以既有 userscript 增加明確、自願、唯讀的一鍵匯入；不得為方便而擴張成持續讀取角色、倉庫、聊天或訂單。

### 4.2 本機保存與角色隔離

- 快照只保存於瀏覽器 IndexedDB。
- 快照不提交 GitHub、不上傳 Pages、不進市場資料檔。
- UI 顯示角色名稱、快照時間及資料完整度。
- 角色名稱及唯一的本機 profile id 共同隔離資料。
- jotaro99、sdve1 及其他角色不得共用裝備、技能或茶設定。
- 支援切換、重新匯入及刪除角色。
- 刪除只影響選定的本機角色資料，不清空其他網站或 userscript storage。

## 5. 雙語物品目錄

HRID 是唯一穩定識別；顯示名稱不是 key。

目錄項目至少包含：

```ts
interface LocalizedCatalogItem {
  hrid: string
  nameZhHant: string | null
  nameEn: string
  categoryHrid: string
  categoryZhHant: string
  sortIndex: number
}
```

產生流程：

1. 從可版本化的 MWI game data 取得 HRID、英文名、分類、配方及裝備資料。
2. 以 Milkonomy 的繁體中文語系資料產生 `nameZhHant`，並保留 MIT attribution。
3. 缺少繁中翻譯時顯示英文，不自行猜譯；build report 列出缺失數與 HRID。
4. 搜尋同時比對繁中、英文及 HRID。
5. 強化等級與精煉狀態分開顯示，不拼進 HRID。

## 6. 策略圖與數值引擎

### 6.1 Domain model

策略圖的節點是「物品＋強化等級」或硬幣；邊是可執行行為：

- `Buy`：市場買入。
- `Gather`：擠奶、採摘、伐木。
- `Manufacture`：鍛造、製作、裁縫、烹飪、沖泡。
- `Decompose`：分解。
- `Coinify`：點金。
- 後續切片再加入 `Transmute`、`Enhance` 及高波動策略。
- `Sell`：市場出售。

每條 action edge 回傳純資料，不直接讀 DOM 或 store：

- 每次輸入與輸出。
- 行動時間、每小時行動數。
- 成功率。
- 茶及其他耗材。
- 精華、稀有與一般掉落的 EV。
- 每小時經驗。
- 所需技能與裝備條件。

### 6.2 價格與稅務規則

預設基準與 Milkonomy 一致：

- 市場購入以最新可用賣一價計價。
- 市場出售以最新可用買一價計價。
- 市場出售收入乘以 0.95。
- 點金產生的硬幣不課市場稅。
- 多步內部中間品不模擬先賣再買，不重複收稅。
- 缺少必要買價或賣價時，路徑標記為資料不足，不補零。
- 自產材料仍有時間成本；「自產免費」不得作為預設假設。

### 6.3 多步路徑

第一階段使用白名單 action graph 產生無循環路徑，最大深度為七步，以覆蓋 Milkonomy 現有多步製造而避免無限循環。

工作流必須：

- 抵消內部生產又立即消耗的中間品。
- 依上游產能與所有下游需求分配工時。
- 在「全買料」「部分自產」「完整自產」間產生獨立候選，不把不同模式混成單一數字。
- 對同一終端產物保留不同有效路徑，不能只以終端 HRID 去重。
- 清楚顯示每步的工時比例、成本、產量與經驗。

### 6.4 首批代表策略

首個垂直切片至少驗證：

1. 一條單步製造策略，例如木板。
2. 一條兩步或三步製造／沖泡策略。
3. 一條分解後點金策略，例如海盜精煉碎片路徑。

這三類先通過 Milkonomy golden parity，再擴展全部配方。強化與轉化因 EV、波動與資金回撤模型不同，不得硬塞入第一批穩定生活策略。

## 7. 流動性與可實現收益

### 7.1 所有市場交易邊都要檢查

不只檢查終端成品。策略使用的每個市場買入與出售項目都需計算：

- 玩家每小時買入／賣出需求。
- 1D／3D／7D 的有效成交量樣本。
- 玩家需求占市場成交量的比例。
- 報價是否單邊、價差是否過大。
- 資料是否新鮮、有無缺口。

第一版只有公開 marketplace 快照時，成交量是 flow-capacity proxy，不宣稱等同完整訂單簿深度。UI 必須說明「成交量承接估計」，不得把未取得的深度或滑價偽造成精確資料。

### 7.2 安全容量

預設安全市占門檻採 Owner 已確認的 5%。基準容量使用 7D 有效逐時成交量中位數，並以 3D 中位數檢查近期偏離：

```text
safe_hourly_capacity = 5% × min(median_3d_hourly_volume, median_7d_hourly_volume)
```

若 3D 或 7D 樣本不足，不能判定可長掛。單日爆量不能單獨解除限制。

每條策略的安全吞吐量取所有市場交易邊中最嚴格者。由此計算：

- 安全製作量。
- 每日可執行時數。
- 理論 24 小時產量。
- 未售或未買足的數量。
- 預估售完天數。
- 安全批量所需流動資金。

### 7.3 分級

- 玩家流量 ≤ 市場安全容量：`可長掛`。
- 等效市場占比 >5% 且 ≤10%：`小倉試單`。
- >10% 且 ≤25%：`限量套利`。
- >25%、缺成交量、單邊或嚴重價差：不得進正常日利排行。

高理論利潤但未通過長掛閘門的策略不刪除，而是進「限量套利」，顯示最多建議數量及估計售完時間。

### 7.4 可實現日利

```text
safe_hours_per_day = min(24, safe_daily_throughput / player_output_per_hour)
realizable_profit_per_day = theoretical_profit_per_hour × safe_hours_per_day
```

若瓶頸發生在買料端，使用可取得原料的安全時數；發生在出售端則使用安全售出時數。介面同時保留理論與可實現值，讓玩家看見被流動性削減了多少。

## 8. 策略趨勢與建議

### 8.1 追蹤策略利潤，而非只追蹤單品價格

對每個歷史快照，以固定角色快照及同一條策略重新計算：

- 原料成本／小時。
- 稅後收入／小時。
- 理論利潤／小時。
- 可實現利潤／日。
- 毛利率。
- 瓶頸市場與安全容量。

由此得到策略本身的 1D／3D／7D 利潤曲線。原料與成品同漲時，系統以利潤變化判斷，不以任一物品漲幅代替策略趨勢。

### 8.2 第一版不用黑箱預測

未累積足夠歷史前，不聲稱精準預測七天後價格。第一版使用可解釋的 deterministic signals：

- `立即執行`：當前可實現日利為正、流動性通過、3D 與 7D 利潤沒有明顯壓縮。
- `趨勢轉強`：3D 策略利潤高於 7D 基準，成交量同步改善，且非單一快照造成。
- `先備料`：目前策略尚未進前列，但原料成本下降／穩定、終端收入及成交量改善，三者至少有兩項成立。
- `等待確認`：價格或利潤改善但成交量未跟上，或樣本不足。
- `趁高出售`：終端價格上升但成交量下降、價差擴大或策略毛利開始壓縮。
- `停止生產`：可實現日利跌破設定門檻、瓶頸市占超標或 3D 利潤明顯低於 7D。

每個建議必須顯示成立原因、信心標籤與具體失效條件，不展示無法解釋的神祕總分。

### 8.3 回測

每次產生歷史 signal 時，只能使用該時點以前的資料。系統記錄 signal 後 3D／7D 的策略利潤變化，計算命中率、平均改善及最大不利變化。

歷史不足時：

- 少於 7 天：只能顯示當前可實現收益，不顯示趨勢推薦。
- 7–29 天：顯示低信心趨勢，不顯示「可能輪動」強結論。
- 至少 30 天且通過回測樣本門檻：才可顯示中／高信心 3–7D 布局訊號。

## 9. 市場歷史保留

目前八日逐時資料足以支援 1D／3D／7D，但不足以驗證輪動訊號。調整為：

- 最近 10 天：保留逐時快照，支援短期容量、價差與量能分析。
- 最近 180 天：保存逐日 OHLCV 及資料品質摘要。
- 日資料由自己的逐時資料彙總，不依賴牛牛股市資料集。
- 雲端中斷時保留缺口，不插值、不用零補齊。
- 發布 payload 維持分塊與上限，避免首頁一次下載 180 天所有逐時資料。

## 10. UI 輸出

策略列表每列至少顯示：

- 繁中策略名稱與完整路徑摘要。
- 建議狀態。
- 理論日利與可實現日利。
- 安全製作量／每日可執行時數。
- 預估售完天數。
- 所需流動資金。
- 3D／7D 利潤方向。
- 信心與主要瓶頸。

策略詳情顯示：

- 每一步輸入、輸出、工時比例與成功率。
- 使用中的技能、工具、服裝、茶、房屋與增益。
- 買料／自產模式。
- 5% 稅及點金免稅處理。
- 每個交易邊的玩家流量、市場容量及占比。
- 悲觀、基準、樂觀情境；未知資料維持未知，不補數字。
- 建議成立原因與失效條件。

## 11. 錯誤與誠實資料規則

- 角色快照過時不阻擋看盤，但策略頁顯示快照年齡。
- 部分匯入不得默默套用高階預設裝備或增益。
- 缺買價／賣價、成交量或必要配方時，策略標記資料不足。
- 零成交、缺價與真實數值 0 必須區分。
- 可實現收益不得超過理論收益。
- 未取得完整訂單簿時不得顯示虛構深度或精確滑價。
- 趨勢訊號不得使用未來資料或用回填資料冒充當時已知資料。
- 所有資料時間以 Asia/Taipei 顯示，保留來源 timestamp。

## 12. 測試與驗收

### 12.1 公式 parity

以固定角色、固定市場 fixture 比較 Milkonomy：

- 單步木板。
- 兩步／三步製造或沖泡。
- 分解＋點金。
- 5% 稅與點金免稅。
- 茶、工具、服裝、房屋、社群增益及神龕。

每個 fixture 明列允許容差及差異原因；不能只比較格式化後文字。

### 12.2 流動性

- 理論高利但產量為市場 50% 時，不得列為可長掛。
- 產量低於安全容量時，可實現日利應等於理論日利。
- 任一原料買入邊成為瓶頸時，整條策略容量下降。
- 缺少 3D 或 7D 樣本時，不得輸出高信心長掛。
- 限量套利顯示安全批量與售完天數。

### 12.3 趨勢

- 原料漲得比成品快時，即使成品上漲，策略仍判定毛利壓縮。
- 單日爆量不應產生高信心輪動。
- 回測不得讀取 signal 時點後資料。
- 失效條件觸發後，建議狀態必須更新。

### 12.4 隱私與 E2E

- 不導入角色仍可完整使用市場看盤。
- 導入 profile 後只寫 IndexedDB，不發出 profile network request。
- 切換 jotaro99／sdve1 不得混用資料。
- 刪除一名角色不影響其他角色及市場自選。
- 雲端不可用時維持安全 fallback，不使用角色資料上傳補救。

## 15. 完成判定

第一個可對 Owner 驗收的版本，必須使用真實角色快照與同一份雲端市場資料，同時展示至少三條代表策略，並證明至少一項 Milkonomy／牛牛股市單獨無法直接回答的決策：

- 排除一條理論日利高但市場無法承接的策略；或
- 找出一條理論排名不是第一、但流動性調整後可實現日利更高的策略；或
- 找出一條 3D／7D 利潤正在改善、具備明確備料條件與失效條件的策略。

若無法提供上述證據，即使頁面、圖表與匯入功能均可運作，也不算完成產品目標。
