# 釘選策略裝備升級 CP／優先級優化器設計

## 目標

玩家釘選一條已通過資料新鮮度、價格、稅金與流動性驗證的策略後，回答：

> 以目前角色快照與市場價格，下一筆資金應買哪一件、哪個強化等級的裝備，才能最快提高該策略的可實現日利？

此功能不屬於「是否值得切換策略」。它只優化玩家已選定的策略，並比較例如 `+5 煉金師下衣`、`+7 煉金師下衣`、`+8 星空工具`、`+5 暴飲之囊` 等互斥或可累加方案。

## 不可妥協的計算原則

1. 每個升級方案都建立一份反事實角色快照，替換指定欄位與強化等級後，重新執行完整 `actionBuffs → 單步／工作流 → 茶消耗 → 5% 稅 → 流動性 → 可實現收益` 資料流；不得只把某個 Buff 百分比直接乘在舊日利上。
2. `inventoryMap` 依 Milkonomy Exporter v1 原始語意，是「持有裝備 HRID → 強化等級」，不是材料堆疊數量。它可判斷已持有裝備及避免重複購買，不得抵扣茶或原料數量。
3. 新裝備採當前強化等級的賣一價；賣掉舊裝備時採對應強化等級的買一價並扣 5% 稅。玩家若選擇保留舊裝備，殘值固定為 0。
4. 裝備加成若提高速度、效率、工匠、美食、成功率、稀有／精華掉落或茶濃度，必須同時重算產量、輸入量、茶耗、掉落 EV、資金需求與市場占比。
5. 缺任一必要買一／賣一、裝備資料、強化乘數或策略市場容量時，方案標記「資料不足」，不得用 0、上一級價格或推測值補齊。
6. 市場快照超過 60 分鐘時不得顯示購買建議；15～60 分鐘只能顯示低信心比較。

## 第一版輸入

- 已釘選策略 ID 與目前固定工序。
- 當前 `PlayerProfile`：技能、已裝備物、房屋、茶、社群 Buff、神龕、成就、封印及 Exporter `inventoryMap`。
- 最新市場各強化等級 `itemHrid::enhancementLevel` 的買一／賣一。
- 玩家可動用預算。
- 舊裝備處理：保留／出售。
- 評估時段：1／4／8／24 小時，沿用策略頁設定。

## 候選生成

1. 從釘選策略實際使用的技能集合判斷有效裝備。
2. 掃描工具、身體、腿部、背部、護符及特殊裝備（例如暴飲之囊）；只保留其非戰鬥屬性能影響該策略至少一個步驟者。
3. 每件裝備展開市場存在的強化等級。玩家已持有且強化等級相同的項目成本為 0，列為基準而非購買候選。
4. 第一階段計算單件替換；第二階段才用受限 beam search 計算多件購買順序，避免貪婪選擇漏掉裝備交互作用。
5. 同一欄位的較低級與較高級方案分開保留，讓 `+5` 與 `+7` 可直接比較；完全被支配者才移到展開區。

## 核心指標

以目前策略為基準 `B`，候選升級為 `U`：

```text
baseline_profit = B 在評估時段內的可實現總利潤
upgrade_profit  = U 在相同時段內的可實現總利潤
incremental_profit = upgrade_profit - baseline_profit

net_cost = 新裝備賣一價 - 舊裝備稅後買一殘值
daily_gain = 升級後可實現日利 - 目前可實現日利
cp = daily_gain / net_cost
payback_days = net_cost / daily_gain
```

另顯示：

- 理論日利增量與可實現日利增量，避免高產量被市場容量吃掉後仍誤判。
- 茶成本增量、其他原料成本增量及稅後收入增量。
- 安全時數變化、本批量變化、瓶頸是否轉移。
- 預算占用、舊裝備殘值、買入價與價格時間戳。
- 相對次佳方案多賺多少，以及額外投入多少。

`daily_gain <= 0`、`net_cost <= 0` 的異常資料、回本期無法計算或策略變成不可實現時，不得列為推薦。

## 排名與建議語言

- **最快回本**：`payback_days` 最短，且可實現日利增量為正。
- **預算內提升最大**：不超過玩家預算者按 `daily_gain` 排名。
- **長期上限最高**：按升級後可實現日利排名，清楚標出成本與較長回本期。
- **下一件建議**：單件購買後重新建立新基準，再算下一件；不把原本的單件 CP 直接串接。

頁面不得只顯示「CP 最高」。建議列至少包含：裝備與等級、淨成本、日利增加、回本天數、茶／原料成本變化、流動性影響及失效條件。

## 組合與購買順序

單件最優不一定是多件組合最優。例如暴飲之囊會同時放大茶效果與茶消耗；工具速度提升也可能使輸出端變成新瓶頸。因此組合版採：

1. 由目前快照建立基準。
2. 展開所有預算內單件升級並完整重算。
3. 保留每層前 N 個非支配狀態（可實現日利高、成本低、回本短、安全時數長）。
4. 對保留狀態再加入下一件裝備，直到達到預算、欄位數或搜尋深度上限。
5. 回傳完整購買順序及每一步的邊際日利，不能只回傳最終套裝。

## UI 位置

第一版放在策略釘選後的展開明細，以「裝備優化」按鈕進入獨立次頁／抽屜；不增加主排行榜欄位。主畫面只在計算完成後顯示一行：

> 下一件：+8 星空工具｜成本 42M｜可實現日利 +1.6M｜約 26.3 天回本

展開頁提供「最快回本／提升最大／長期上限」三種排序，以及目前裝備與候選的逐項差異。

## 實作階段

1. **資料契約與單件重算**：建立裝備市場候選、反事實 profile、成本與殘值模型、單件完整重算及 golden tests。
2. **釘選策略 UI**：比較表、預算、保留／出售舊裝備、資料不足與失效說明。
3. **組合搜尋**：非支配 beam search、購買順序與每一步邊際收益。
4. **強化自製路線（另案）**：只有在取得並驗證強化成功率、保底、材料消耗與失敗結果後，才比較「直接買 +N」與「自行強化」。第一版不得用期望值猜測未驗證的強化機制。

## 驗收

1. 更換裝備後茶效果與茶消耗同步變動。
2. 速度提高造成市場瓶頸時，可實現日利增量小於理論增量，排名採前者。
3. `inventoryMap` 的數字只作裝備強化等級，不作材料數量。
4. 舊裝備出售殘值正確扣 5%，點金免稅規則不被誤套用到裝備。
5. `+5` 與 `+7` 同件裝備均可比較，且顯示額外成本換得的邊際收益。
6. 暴飲之囊提高 Buff 時同時計入增加的茶成本。
7. 缺價、舊資料、負增益及超預算方案不會被推薦。
8. 每次購買後下一件優先級會以新快照重算，不沿用舊 CP。
